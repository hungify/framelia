Publish immutable run/case/attempt bundles with exact membership and finalization, alongside the existing dashboard/`VerificationArtifact` path (unchanged).

- `@framelia/verify` adds a new `./run-bundle` subpath: `freezeRunPlan`/`readRunPlan` publish and read a run's frozen `RunPlan` plus every collected case's full `CasePlan` record (not just its digest) as one immutable bundle unit; `publishAttempt` stages an attempt's evidence (`expected.png`/`actual.png`/`diff.png`/`score.json`) and its own schema-valid `AttemptRecord` and publishes them as a single atomic, collision-rejecting bundle unit (stage-then-rename onto a fresh directory, refusing a non-atomic cross-device fallback); `startRunRecord`/`publishRunRecord`/`finalizeRunRecord` manage the run's own coordination record (`status: "planned"|"running"` -> `"finalized"`), recomputing each case's `attemptIds`/`selectedAttemptId` by scanning its attempts directory rather than trusting an incrementally-mutated list, so concurrent workers publishing attempts for the same run never race on a shared file; `readRunBundle` resolves an entire run (plan, case plans, run record, every attempt) from disk, revalidating every recorded digest, using only project-root-relative paths so a copied bundle resolves without the writer's own checkout. New `AppErrorCode` members `RUN_BUNDLE_ALREADY_PUBLISHED`, `RUN_BUNDLE_CROSS_DEVICE`, `RUN_BUNDLE_MISSING`, `RUN_BUNDLE_INVALID`, and `RUN_BUNDLE_DIGEST_MISMATCH` cover its failure modes.
- `@framelia/contracts`'s `attemptRecordSchema` now rejects a `visualVerdict: "passed"` attempt whose `executionState` isn't `"completed"` -- skips, blocks, incomplete runs, and errors can never resolve to a visual pass. `SourceIdentity`, `RunSelection`, and `Diagnostic` are now exported types.
- `@framelia/playwright`'s `FrameliaReporter` freezes a `RunPlan` (and every collected case's `CasePlan`) at `onBegin` for every `framelia.contract`-annotated test the suite collected, publishes an `AttemptRecord` per test result at `onTestEnd` (mapping skipped/timed-out/interrupted/errored results to a non-passing `executionState`, never a silent pass), and finalizes the run record at `onEnd` -- all independent of the optional dashboard/`VerificationArtifact` path, so a missing `@framelia/dashboard-server` peer dependency or a dashboard start failure can never prevent durable run-bundle recording, and vice versa. New `FrameliaReporterOptions.runId`/`source` let a caller pin the run id and fold in known source/build identity. A run with zero `framelia.contract`-annotated tests (or an uninitialized project with no resolvable policy digest) is silently skipped -- an ordinary matcher-only suite never gets a run bundle.
