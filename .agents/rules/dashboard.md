# Dashboard (apps/dashboard)

Vue 3 + Vite + Nuxt UI + Tailwind 4, file-based routes in `pages/`. It renders verification state only: capture, comparison, gating and persistence stay in `@framelia/verify` and the cli. See `apps/dashboard/README.md` for running it against a real run bundle.

- Data arrives from the CLI/Reporter HTTP API and SSE (`data-source.ts`) and is validated against the `@framelia/contracts` dashboard schemas before use. A new field starts in contracts, then the projection in `@framelia/dashboard-server` / cli, then the UI.
- `typed-router.d.ts`, `components.d.ts` and `auto-imports.d.ts` are generated by Vite plugins on `pnpm dev:dashboard`; regenerate, never hand-edit.
- `pnpm dev:dashboard` runs against `mocks/dashboard.ts`. When the UI gains a new state (status, baseline kind, capture kind, inspector mode, missing evidence), add it to the mock so the preview keeps covering every state.
- Logic lives in `lib/` (pure functions) and `composables/` (`use<Thing>`), each with a test in `tests/` named after the file (`contract-tree.test.ts`, `use-canvas-view.test.ts`); components stay thin. These are also the files mutation testing covers.
- UI uses Nuxt UI components and Tailwind theme tokens; evidence images carry alt text.
- `pnpm build` (or the dashboard-server build) writes the production bundle to `packages/dashboard-server/dist/dashboard`, which ships in that package; `pnpm size` checks its budgets (`.size-limit.json`). `vue-tsc --noEmit` is its typecheck.
