# Framelia reference app

Standalone TanStack Start consumer app showing Framelia around a real Better Auth flow: login/signup, protected dashboard, profile settings, logout, deterministic auth fixtures, and all three Framelia Playwright matchers.

This example intentionally lives outside the root pnpm workspace. It keeps the generated Mugnavo architecture: TanStack Start, shadcn/ui + Base UI, Better Auth, Drizzle/PostgreSQL, Vite+, Nitro, and Playwright.

## Requirements

- Node.js >= 24
- pnpm >= 11
- Docker, for local PostgreSQL
- Chromium, via `pnpm exec playwright install chromium`

## Local setup

```bash
cd examples/framelia-reference-app
cp .env.example .env
cp .env.playwright.example .env.playwright
pnpm install
# Set BETTER_AUTH_SECRET in .env; `pnpm auth:secret` can generate one.
docker compose up -d
pnpm db:setup
pnpm dev
```

Open `http://localhost:3000/login` and create an account through the real signup flow. Runtime app uses `.env`. Playwright loads `.env.playwright` for test-only values, then exercises the same app server and `tanstarter` database from `.env`.

Playwright auth setup uses real signup/login UI against Better Auth + PostgreSQL. Default deterministic test credentials come from `.env.playwright`:

```text
Email: demo@northstar.local
Password: northstar-demo-password
```

Auth uses generated Better Auth with Drizzle/PostgreSQL. Protected routes live under `src/routes/_auth`; unauthenticated access redirects to `/login`. Successful email login/signup redirects to `/app`. `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL`, and `DATABASE_URL` stay server-side.

## Tests

Playwright config creates `playwright/.auth/user.json` through a real signup/login flow. Auth state is ignored by Git. `.env.playwright` contains only `PORT` and `E2E_*` credentials; app secrets and database URL remain in `.env`. Projects are separate:

```bash
pnpm test:unauth
pnpm test:auth
pnpm test:e2e
pnpm test:e2e:real-flow
pnpm test:web
pnpm test
```

`e2e/specs/public.spec.ts` checks login/signup availability and protected-route redirects. `e2e/specs/authenticated.spec.ts` uses `storageState` for dashboard/settings/logout checks. Page objects live under `e2e/pages`; fixtures own their construction under `e2e/fixtures`. Stable `data-testid` hooks target login, dashboard, and settings proof surfaces.

## Framelia matchers

`playwright.config.ts` registers `@framelia/playwright/reporter`. Reporter starts its dashboard integration and writes durable Figma evidence under `.framelia/visual-verifications/` when a Figma matcher runs. `e2e/fixtures/auth.setup.ts` creates/logs into the demo account through the real signup/login UI; no fake seed path exists.

### `toMatchPage`

`e2e/specs/web-to-web-page.spec.ts` prepares login in two pages with different fixture query values, then compares both. No Figma credentials required.

### `toMatchUrl`

`e2e/specs/web-to-web-url.spec.ts` compares `/login` with a second login fixture URL in the same browser context. Cookies and auth state carry across when used on protected routes. No Figma credentials required.

### `toMatchFigma`

`e2e/specs/figma.spec.ts` reads the login baseline generated by `framelia contract create` at `.framelia/visual-verifications/login/visual-contract.json` and is gated by the Figma API token:

```bash
FIGMA_ACCESS_TOKEN=... \
pnpm test:figma
```

The contract owns route, file key, node ID, viewport, and scope. `FIGMA_ACCESS_TOKEN` is the only Figma secret.

## CLI showcase

This app exists to exercise Framelia as a real consumer. Run these commands from this directory:

```bash
# Initialize a disposable Framelia project config.
pnpm cli:init

# Inspect installed CLI/runtime capabilities.
pnpm cli:status
pnpm cli:schema

# Open browser auth capture and save configured storage state.
pnpm framelia auth --url http://localhost:3000/login

# Create login's schema-v4 visual contract interactively.
# CLI writes .framelia/visual-verifications/login/visual-contract.json by default.
FIGMA_ACCESS_TOKEN=... pnpm cli:contract:login
```

Run visual tests to produce matcher attachments and, with Figma credentials, persisted artifacts:

```bash
pnpm test:web
pnpm test:figma
```

Inspect live or persisted evidence with CLI:

```bash
pnpm cli:dashboard
pnpm framelia open --artifact .framelia/visual-verifications/<id>/visual-verification.json --no-open
pnpm framelia report \
  --artifact .framelia/visual-verifications/<id>/visual-verification.json \
  --output .framelia/reports/latest
pnpm done-gate -- --artifact .framelia/visual-verifications/<id>/visual-verification.json
```

Capture and compare standalone Figma PNGs:

```bash
pnpm framelia fetch-gold \
  --file-key "6OWioRfOFWhE2ymylsPSH4" \
  --node-id "1037:71575" \
  --out .framelia/figma-gold.png
pnpm framelia compare \
  --gold .framelia/figma-gold.png \
  --actual .framelia/visual-verifications/<id>/actual.png \
  --out-dir .framelia/comparisons/latest
```

`dashboard`, `open`, `report`, `fetch-gold`, `compare`, and `done-gate` consume the artifacts produced by the tests. `done-gate` validates Figma-baselined persisted evidence. Web-to-web matcher output remains Playwright attachment/dashboard evidence by design.

## Verification gates

```bash
pnpm typecheck
pnpm lint
pnpm format:check
pnpm build
pnpm test:unauth
pnpm test:auth
pnpm test:web
```

`pnpm check` runs Vite+ format/lint checks. Database gates require PostgreSQL. Figma gate requires valid credentials and a real node ID.

## Deployment

Nitro is configured by the generated Vite+ setup and supports Netlify, Vercel, Node, and other Nitro presets. Choose provider through its official TanStack Start/Nitro deployment path; set `NITRO_PRESET` when provider requires it.

Required deployment variables:

```text
DATABASE_URL
BETTER_AUTH_SECRET
BETTER_AUTH_URL
```

Figma credentials are not part of the app env contract. Provide them only when running the optional Figma matcher, using local shell variables or CI secrets. Never expose server secrets through `VITE_*` variables. Run `pnpm db:migrate`, deploy, then smoke-test `/`, `/login`, `/app`, and `/app/settings` with a real account.
